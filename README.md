# dsh-pixiv-aesthetic

> DSH 插件：按你的口味刷 Pixiv —— 搜、筛、**看图精选**，存到本地或发给你。

**⚠️ 网络：** 能上 pixiv 时全功能。上不了时有一条**无代理通道**（第三方 HibiAPI + 图片镜像），
能搜能取图，但**搜索词会经过第三方**、而且随时可能断 ——
详见 [网络：能上 pixiv 和上不了 pixiv 的区别](#网络能上-pixiv-和上不了-pixiv-的区别)。

设置页和插件面板里显示的名字是 **`Pixiv 美学漫游`**；包名仍是 `dsh-pixiv-aesthetic`。
两者不一样是**故意的**（显示名是另外指定的写法，包名跟站点名对齐更好认）。

和「刷B站」是同一套路子的姊妹插件。区别在于 Pixiv 是**图片**，所以多了一层
「真的把图看一眼再挑」。

**零配置就能用**，不需要登录。能上 pixiv 时走官方；上不了时自动退到无代理通道（可关）。
想更贴合口味可以选开登录（拿关注流和个性化推荐，**这个必须能上 pixiv**）。

---

## 它做什么

- 按关键词 / 排行榜找候选，按标签权重、画质、新鲜度打分排序
- **元数据先粗筛**（分级、页数、分辨率、排除标签、判重），再**读图精选**
- 存成 `<根>/<画师>/<标题>_<ID>/001.jpg …` + `metadata.json`（含 sha256、来源、判定理由）
- 发给你（走投递通道；没配通道就只落盘，**默认永远能用**）
- 可选定时刷（谷时自跑）
- 可选登录（多拿关注流 + 个性化推荐）

## 网络：能上 pixiv 和上不了 pixiv 的区别

插件**不内置代理节点、不伪造/加密 SNI、不连 pixiv 的真实 IP**。能上 pixiv 时它走官方；
上不了时，它能做的只有两件事：**借第三方 API 拿元数据**、**把图片镜像固定到 Cloudflare 节点 IP**（绕开镜像域名的 DNS 污染）。

历史口径（2026-11-05）：当时写的是「上不了 pixiv 这插件就没用」，理由是「发现图片需要元数据接口，
镜像站一个都没有；只知道作品 ID 不够，而知道 ID 本身就意味着你已经能发现它了」。
这个判断**对镜像站仍然成立**，但漏了 HibiAPI 这类「替你调 App API」的第三方服务。
**2026-11-09 起不再成立** —— 多了一条**无代理通道**，外部源 / 直连 / 代理都不通时自动顶上：

| 环节 | 无代理通道怎么做 | 实测（2026-11-09，本机无代理） |
|---|---|---|
| **发现**图片（搜索 / 排行 / 详情） | 第三方 **HibiAPI** 公共实例（`hibiapi.getloli.com`）转发 pixiv App API | 排行 30 条、搜索 30 条；单次 1~17 秒，偶尔超时 |
| **取**图片字节 | `i.pixiv.re` 镜像，**TCP 固定连到 Cloudflare 节点 IP**、SNI/Host 仍是域名 | 缩略图 60KB 秒出；24MB 原图 22 秒 |

⚠️ 代价，开之前想清楚：

- **搜索词会发给 HibiAPI 的服务器**（第三方）。登录 token **不走**这条路。
  介意就在设置页关掉，或者自建一个 HibiAPI 实例填进去。
- **这条路只验证过一天，随时可能断**：公共实例时快时慢；Cloudflare 节点
  对不同文件快慢能差上百倍（插件会换节点、掐掉低于 100KB/s 的连接）。
- **登录相关功能（关注流 / 推荐）在这条路上用不了** —— 它们要直连 App API。

> 为什么不是 pixivpy 的 ByPassSniApi：它靠 DoH 拿 pixiv 真实 IP、再连过去。
> 本机实测 pixiv 真实 IP 段全部 443 超时、DoH 也连不上，两半都断，所以没采用。
> 固定 IP 只用在**镜像**上（镜像的系统 DNS 被污染，固定到 Cloudflare 节点就通）。

> 旧实测（2026-11-05）仍然成立：`pixiv.re` 镜像本身**没有**元数据接口（`/ajax/*`、
> `/ranking.php`、`/api/*`、`/search/*` 全 404），所以元数据必须另找 —— 这就是 HibiAPI 那半。

### 五条路

插件会在**五条路**里自己挑：

| 路 | 什么时候用 |
|---|---|
| **外部源** | 你填了 `externalApi` —— **优先级最高**，见下 |
| **直连** | 你的机器本来就能通（比如挂了 TUN 模式的代理） |
| **代理** | 你填了 `proxyUrl`（如 `http://127.0.0.1:7897` 这类本地代理） |
| **HibiAPI** | 前三都不通、且没关 `hibiEnabled` 时，元数据走它（**第三方**，见上） |
| **镜像** | 拿图兜底：`pixiv.re`，系统 DNS 不行就固定到 Cloudflare 节点 IP |

判定方式是**实际探测**（并行试外部源/直连/代理，看谁真能拿到数据；都不通才去试 HibiAPI），不是按 IP 猜。
实测数据：同一台机器十分钟内 TUN 时通时不通、裸直连整体超时、走代理 3/3 通
—— 所以「通不通」是探测出来的，不是写死的。

## 「外部源」——接你自己能上 pixiv 的东西

**这是给"上不去 pixiv"准备的唯一出口。**

如果你的机器上已经有**任何能访问 pixiv 的东西** —— 自建反代、自己的服务器、
某个能上 pixiv 的客户端 —— 把它的地址填进 `externalApi`，插件就走它。

### 怎么填

设置页 → 网络 → **外部源**，填一个地址：

```
http://127.0.0.1:8080              # 本机跑的
https://你的反代.example.com        # 自己的反代
https://你的服务器.com/api/pixiv    # 带子路径也行
```

**约定：那个地址要兼容 pixiv 官方接口形态。** 插件保持官方路径不变，只换 origin：

```
https://www.pixiv.net/ranking.php?mode=daily
      ↓  换成你的地址
https://你的反代.example.com/ranking.php?mode=daily
```

也就是说，只要你的反代**把 pixiv 的路径原样转发**，插件就能用它 ——
搜索走 `/ajax/search/artworks/*`、排行走 `/ranking.php`、详情走 `/ajax/illust/*`。

### 插件做什么、不做什么

- **不做**：内置代理节点、伪造 / 加密 SNI、硬连 pixiv 真实 IP。
- **做**：无代理通道里，元数据借第三方 HibiAPI；图片镜像的域名 DNS 被污染时，
  把 TCP 固定连到 Cloudflare 节点 IP（SNI / Host 仍是镜像自己的域名，不伪装成谁）。
  这条通道**默认开**，设置页「网络」里能关。
- 外部源那个口子还留着：你有自己的反代 / 服务器，填进来优先走它。

> 参考：`PixEz` 的「免代理直连」用的是硬编码 pixiv 真实 IP + DoH
> （`lib/er/hoster.dart`）或 ECH 加密 SNI（`lib/network/network_mode.dart`）；
> pixivpy 的 `ByPassSniApi` 同理。本机实测 pixiv 真实 IP 段 443 全超时、DoH 连不上，
> 这一路在这台机器上走不通，所以没采用。

### 优先级

**外部源 > 直连 > 代理 > HibiAPI。** 你填了外部源就是明确说了走它 ——
插件不会自作主张绕开它去直连（那等于无视你的配置）。HibiAPI 排最后，因为它把搜索词交给第三方。

插件会在设置页和工具返回里**如实告诉你现在处在哪一档**，不会让你对着"搜到 0 条"猜：

```
官方直连 ✓ · 镜像 ✓          ← 全功能
官方经代理 ✓ · 镜像 ✗        ← 全功能
HibiAPI ✓（第三方，无代理） · 镜像 ✓（固定 104.x.x.x …）  ← 能搜能取图，登录功能不可用
官方 ✗ · 镜像 ✓
  → 只能按作品 ID 取图，不能搜索/排行（镜像没有元数据接口）
官方 ✗ · 镜像 ✗
  → 完全打不通 pixiv。检查代理是否在跑（当前：…）
```

### 2. DSH 的聊天框不支持助手发图

这不是插件的限制，是宿主的：官方 `dsh-attachment` 只做**用户 → 模型**的单向传递，
assistant 侧的图片输出目前只是 forward-compatibility，生产适配器只声明 text-only。

所以「发给你」只能走**投递通道**：

| 通道 | 说明 |
|---|---|
| `local` | **默认，永远可用**。存到 `saveRoot`，并报告绝对路径 |
| `qq` | 可选。需要你自己装 QQ 机器人（见下） |

> 设计上刻意做成**通道接口**：QQ 只是其中一个适配器。
> 别人没装 QQ 机器人也能用，默认那条「存到本地」不依赖任何外部配置。

### 3. QQ 通道的两条限制

- 插件**不带任何凭证**，`appId` / `appSecret` 全靠你自己配
- **QQ 机器人默认没有主动消息权限**：不带宽内 `msg_id` 直接发会被拒（HTTP 400 / code `40034105`）。
  只能在收到消息后约 **5 分钟**内的「被动窗口」里回。
  窗口过了插件就**只落盘**，并如实说明原因 —— 不会假装发出去了。

## 安装

```bash
# ① 从 npm（推荐 —— 这样在 DSH 的插件列表里能直接搜到）
dsh plugin --profile <你的profile> add dsh-pixiv-aesthetic

# ② 从 GitHub（没发 npm 或想用主分支时）
dsh plugin --profile <你的profile> add github:AcerGL/dsh-pixiv-aesthetic

# ③ 本地目录开发（改代码即时生效）
dsh plugin --profile <你的profile> add link:<插件目录>
```

> ⚠️ **只有 registry（npm）装的包会出现在 DSH 的「可安装插件」列表里** ——
> 那份列表是查注册表得到的。走 ② / ③ 的话**得手输上面那条 spec**，搜不到。

装完**必须重启一次 DSH**（bundle 层要重启才组装，客户端 bundle 也只在启动时读）。

`dsh plugin` 会自动做三件事，**不用手改 profile 的配置文件**：

1. 用 pnpm 把包装进 `$DSH_HOME/profiles/<profile>`
2. 因为本包声明了 `dsh.bundle`，把它加进 profile 的 `dsh.profile.bundles`
3. 启动时应用包内自带的 `cordis.patch.yml`

### 版本兼容

本包在 `package.json` 里声明了：

```json
"engines": { "dsh": ">=0.2.0-rc.2", "node": ">=22" }
```

`engines.dsh` 是 DSH 的**准入闸门**：DSH 启动导入插件前会拿它跟运行时版本比对，
不满足就不加载（并列入 `skippedBundles`）。判定用的是
`semver.satisfies(v, range, { includePrerelease: true })`，所以预发布版
（如 `0.2.1-rc.3`）也能正常落在范围内。

真被拒了的话，DSH 会打印精确的豁免命令：

```bash
dsh plugin --profile <profile> allow-version <pkg@ver> --dsh-version <runtime> --accept-risk
```

（豁免存在 profile 的 `compatibility.json`，插件或 DSH 一升级就失效 —— 要重新授权。）

### 桌面版注意

桌面版（Electron）里 `dsh` **不在 PATH** 上。要手动跑命令的话用：

```
<安装目录>\resources\runtime\cli\bin\dsh.cmd
```

这个包装内部已经设好 `ELECTRON_RUN_AS_NODE` 并带上 `--expose-internals`。

定时刷也需要它 —— 在设置页把 `dshBin` 指到这个路径。

## 设置页

装好后进 **设置 → Pixiv 美学漫游**。里面分几组：

| 组 | 有什么 |
|---|---|
| **总开关** | 一键停用（定时轮也停） |
| **网络** | 代理地址、图片镜像，和一个 **「测一下」** 按钮 |
| **找什么** | 关键词（回车加入，点 ✕ 移除）、排行榜池塘 |
| **口味** | 排除标签、必须标签、收藏下限、时间窗 |
| **账号喜好** | 看现在记的是谁、立即读一次、**只重置账号那份** / **完全重置** |
| **分级** | 收 R-18（**默认关**）、过滤 AI 生成 |
| **登录（可选）** | 开关、刷哪些池子、贴 token、查看状态、退出 |
| **存放** | 保存根目录、目录模板 |
| **额度** | 每天最多存 / 一次最多挑 / 单件最多几页 |
| **发到哪** | 存到本地 / 发到 QQ |
| **定时** | 间隔分钟数、谷时开关（中午 / 晚上） |
| **状态** | 家目录、配置文件路径、全面自检 |

**「测一下」** 会告诉你当前的实际情况，比如：

```
网络：官方经代理 ✓ · 镜像 ✗
登录：未使用登录（游客模式）
额度：今天已存 3/6，还能 3
通道：存到本地 ✓  发到 QQ ✗（没窗口）
存到：D:\Pixiv
```

配置**真值**在 `$DSH_HOME/pixiv-scroll/config.json`，改动即时生效（不用重启）。

> ⚠️ 为什么不写 profile：profile 里 entry 的 `config` 段**不进插件 user 层**，
> 宿主那边始终是 schema 默认值。所以改 profile 对运行期无效，改设置页才有效。

## 登录（可选，默认关）

**不登录也能用**（游客模式：排行榜 + 搜索）。登录后能多拿两样：

- **关注流** —— 你关注的人的新作
- **个性化推荐** —— 这个才是"更符合喜好"的正主

### 为什么走 App API 而不是网页登录

实测（2026-11-04）用网页 cookie 请求这些接口**全是 404**：

```
我的关注流 / 我的收藏 / 推荐 / 为你推荐 / 我的资料
```

所以登录走 **`app-api.pixiv.net` + Bearer token**，需要你提供一个 `refresh_token`。

### 三条安全线

| 项 | 做法 |
|---|---|
| 权限 | **只申请 `readonly`** —— 从权限上就不可能点赞/收藏/关注/评论 |
| 存放 | token 只写 `credential.json`，**不进配置、不进日志、不回显** |
| 轮换 | pixiv 每次刷新**换发新 token**（旧的立即失效）→ 刷新后立刻落盘 + 文件锁 |

代码里有两道闸门挡着凭证：HTTP 接口层删一次，`saveConfig` 里 `SECRET_KEYS` 再删一次。
自检里还有一条断言专门验「client.js 没往 localStorage 写东西」。

### 怎么拿 refresh_token

插件**不做**账号密码登录 —— 那要起浏览器过 reCAPTCHA，在国内网络下成功率不高，
而且会让你的密码经过插件。请自行获取 `refresh_token` 后贴进设置页。

> ⚠️ 如果你在**别的地方**也用了同一个 token，两边会互相踢掉（因为轮换）。
> 踢掉了就重新贴一个。

### 登录坏了会怎样

**不影响刷图。** 登录是可选的，它出问题只是少两个池子。
自检里有一条断言专门验这个：打桩让关注流和推荐**双双失败**，`pixiv_search`
仍然正常出结果，只是如实报告"这两个池子为什么没成"。

> ⚠️ **登录 ≠ 能读**。凭证有效、设置页显示"已登录"，但换 token 的那一步走不通时
> （本机实测：`oauth.secure.pixiv.net` 被墙），照样读不到任何东西。
> 插件会把这种情况说成"登录着但这会儿换不到 token"，**不会**骗你说没登录 ——
> 免得你白去重新登录一遍。

### 账号喜好（从你登录的 pixiv 账号读来的那份）

登录着的时候，插件会顺手把你**账号收藏**里体现的喜好记下来，单独存一份。
这样以后**没代理**时也能优先按你的喜好找图，而不是只在每日榜里无脑搜。

规则（都是刻意的，别当 bug）：

| 情况 | 账号喜好算多大 |
|---|---|
| 本机还没热身（存够 5 件之前） | **占大**（×1.0）—— 本机还没自己的口味，就用你的 |
| 本机已经热身 | 只当**零头**（×0.2）—— **以本机跑出来的为主** |
| 刚重置过、本机还没重新攒够 | **占大**（×1.0）—— 重置就是"让账号那份接管"的开关 |

- **只记第一个账号**。后来换了账号、又没重置 ⇒ 不覆盖，而是从那一轮起
  **每轮往前挪一格**（约十轮移完）慢慢把权重移到最新登录的账号上。
- 想**立刻**换：用「只重置账号喜好」，下一个登录的账号会被重新读取并直接占大。
- 两种重置：
  - **只重置账号喜好** —— 本机画像一点不动，只清账号那份。
  - **完全重置** —— 本机画像 + 账号喜好都清掉。⚠️ 但「不想看 / 删过了」那份清单**留着**：
    那不算画像，清掉的话你删过的图会全部再冒出来。
- 两条硬约束：账号喜好**只加正向**（不会学出负口味），而且**永远不会**盖过
  "分级过滤 / 判重 / 删过了 / 不喜欢"—— 那些是明确指示。

> 抓取只走**官方 API**（要 token），**永不经第三方**（HibiAPI 用的是它自己的 token，
> 读不到你的账号）。全程只读。

## 给 Agent 用的工具

| 工具 | 干什么 |
|---|---|
| `pixiv_status` | 网络走哪条路、登录态、口味画像、今天存了几件、额度剩多少、通道哪些可用 |
| `pixiv_taste` | 看 / 调**口味画像**（自动学出来的偏好）。默认关；开关它、改权重、清空重学都在这儿。也能看/重置**账号喜好**（`account` / `resetAccount` / `reset`） |
| `pixiv_feedback` | 记审美反馈：不喜欢这张 / 不要这个画师 / 不要这种风格。**三类扣的东西不同**，不会一刀切 |
| `pixiv_explore` | 智能漫游：按画像推荐 / 有控制地探索新画师 / 从某张往外走 / 把情绪转成搜索计划。理由可解释，**没读图就说没读图** |
| `pixiv_search` | 找候选（含打分与为什么；画像开着时会按口味反搜） |
| `pixiv_pick` | 下缩略图到本地，好让模型 `read_image` 真的看一眼再挑 |
| `pixiv_works` | 取原图（只下载，不占额度） |
| `pixiv_save` | 正式收进图库（**唯一占额度的操作**，过分级/判重/额度闸门） |
| `pixiv_send` | 投递出去（落盘 / QQ） |

推荐的用法顺序：

```
pixiv_status → pixiv_search → pixiv_pick（读图精选）→ pixiv_save → pixiv_send
```

> `pixiv_pick` 需要有视觉能力的模型。纯文本模型读不了图，那就跳过这一步，
> 直接按 `pixiv_search` 的打分选，并在报告里说明这轮没读图。

## 定时刷

设置页把 `intervalMin` 设成大于 0（单位分钟）就会定时跑。

谷时规则：工作日 **9–12 / 14–18** 是高峰，其余（含周末）都算谷时，
由 `peakValley` / `noon` / `night` 三个开关控制。

### 浮窗（右侧停靠面板）怎么接才显示

**这一步很容易做错，记一下正确形状。** 注册分**三步**，少一步 tab 就不出现，
而且**不会有任何报错** —— 表现就是「右侧面板还是只有原来那些东西」。

```js
// ① 声明"有这么一类 tab"
ctx.sidebarRightTabs.register({
  id, kind, priority: 'builtin',
  title: () => '这一轮',
  canOpen: (address) => String(address) === id,
})

// ② 这个 tab 的正文
ctx.slots.inject('sidebar.right.pane.tab', () => ctx.slots.register(
  { name: 'sidebar.right.pane.tab', key: id }, Body))

// ③ 这个 tab 在标签条上的标题 chip   ← 最容易漏的一个
ctx.slots.inject('sidebar.right.pane.tab.title', () => ctx.slots.register(
  { name: 'sidebar.right.pane.tab.title', key: id }, Title))
```

还有两条同样重要的：

- **注册 ≠ 显示。** 上面只是声明了"类型"，还得有人调
  `ctx.sidebarRight.openTab(kind, …)` 才会真的实例化一个标签页。
  官方是由某个入口（点 Session 里的卡片之类）触发的；本插件没有那种入口，
  所以加载后自己开。
- **`inject` 里只能放真的必需项。** 这是踩得最狠的一条：
  inject 里**缺任何一个服务，宿主根本不跑 `apply()`** ——
  于是不只是浮窗没有，**连「设置页」那一项也一起消失**，且完全静默。
  所以浮窗那两个服务（`sidebarRightTabs` / `sidebarRight`）在 `apply()` 里
  现取、拿不到就降级，**绝不放进 `inject`**。

### 过度区（staging）—— 「看得见就一定存得下」

**要解决的问题**：原来 `pixiv_pick` 只下一张**缩过的**预览图，点「存」的时候
要**回 pixiv 重新下原图**。要是那一刻网络抽风（或者代理掉了），就会出现

> 「图我明明看得见，点存却说下不来」

**做法**：预览的时候就把**原图**也存到 `staging/`，点「存」变成**搬一下**，
不再重新下载 —— 只要你看过，就存得下。

```
<家目录>/staging/<这一轮>/<作品id>/001.png      ← 原图（点存时搬走）
<家目录>/library/<画师>/<作品>_<id>/            ← 主图库（你点了存才进）
```

**清理按「轮」，不掐表**：下一轮开始时清掉上一轮。
不搞「N 分钟后自动删」是有意的 —— 那玩意会在你边看边挑的时候把图删掉，
缩略图当场变破图，而且**没法重下**。

| 设置项 | 默认 | 说明 |
|---|---|---|
| 过度区 | **开** | 关掉就退回老做法（预览只留缩图，点存时再下原图） |

⚠️ 打开会**占地方**（一轮 10 张原图 ≈ 100MB）。清理只在你开下一轮时发生，
所以如果你开了一轮就再也没开过，那份东西会一直躺着。
想立刻清就在设置里关掉过度区，或者手动删 `staging/` 目录。

> 🔴 **清理逻辑只许动 `staging/`**，绝不碰 `library/`。
> 路径校验跟删除键一个规格，自检里有专门断言钉着
> （"清理**绝不动主图库**"）。

### 画面特征那一层（阶段 C）

`pixiv_pick` 下完缩略图后，会顺手用 **Pillow 量一遍画面特征**：亮度、对比度、
饱和度、色温偏向、主色、边缘密度、三分法落点。这些是**数字**，不是描述。

**为什么不调视觉模型**：规格里钉了两条自我约束 ——「不得伪造相似度」、
「不得把未知评分伪装成概率」。如果我们让模型"描述一下这张图"再写进推荐理由，
那就是把编出来的话当成分析结果。而 Pillow **量得出来**的东西是可复现的、
能被自检逐条验的；量不出来的「好不好看」就**留空**，不猜。

所以 `pixiv_explore` / `explain()` 里有**三态**，必须分清：

| 状态 | 什么时候 | 它怎么说话 |
|---|---|---|
| **读过图** | agent 用 `read_image` 真看了 | 「读过图（置信度 …）」 |
| **只量过** | Pillow 量了特征，但**没人看** | 「**没人看过这张图**，但画面特征是量过的：明亮 · 高饱和 …」 |
| **都没有** | 分析没做/失败 | 「**没有读图** —— 只从元数据推的」 |

中间那一态刻意**不并进"读过图"**：数值可信，但"这张画得好不好"没人替你把关，
混为一谈就是不诚实。

> 这一层挂了**不影响主流程**：缩略图照样给你，只是标注"没量成"，按"没读图"算。

### 为什么传输层是手搓的

运行时里**没有 `undici` 也没有 `sharp`**（都只在 `app.asar` 里，`require` 和 `fs` 都进不去）。
所以：

- 传输层自己 CONNECT 隧道 + 自己 TLS 握手 + 自己拆 chunked
- 缩图 shell 出去走 Python/Pillow

顺手绕开的坑（都写了注释，别改回去）：

- `socket.setTimeout()` 只在 socket **空闲**时触发 —— 连接卡在建连阶段时永不触发，
  会**永久挂死**。必须有独立硬超时。
- TLS 握手期间就要 `track()` socket，否则每次失败漏 2 个连接。
- `_inflight` 存了已 reject 的 promise 会变成 unhandled rejection，**默认直接杀进程**。

## 已知限制（如实写，不粉饰）

- 🔴 **无代理通道靠第三方，随时可能断**。HibiAPI 公共实例时快时慢（实测 1~17 秒、偶尔超时），
  而且**搜索词会经过它**；镜像固定的 Cloudflare 节点 IP 也可能变。断了就报人话，不会静默返回 0 条。
  不想把搜索词给第三方：设置页关掉「无代理通道」，或填自建 HibiAPI。
- **无代理通道下登录功能不可用**（关注流 / 推荐要直连 App API）。
- **镜像本身没有元数据接口**。`pixiv.re` 实测 16 条路径，只有图片路径通，
  `/ajax/*`、`/ranking.php`、`/api/*`、`/search/*` 全 404 —— 所以元数据得靠 HibiAPI 或官方。
- **R-18 过滤是尽力而为**。默认只做**元数据层**过滤（标签 + 内容标记），
  不逐张读图复查。排行榜原始数据里本来就混着露骨封面的作品
  （实测 `daily` 前 50 条里有 5 条带性内容标记），所以会有漏网。
- **QQ 发图受被动窗口限制**。见上文。
- **登录需要自己搞 `refresh_token`**。插件不代你登录，也不碰你的密码。
- **定时刷需要一个 `dshBin` 路径**。桌面版 `dsh` 不在 PATH，要在设置里指过去。
- **代理不在时会连不上**。本机代理软件（Clash 之类）没在跑就通不了，
  插件会报人话而不是静默失败。
- **探测结果受本机网络环境影响**。同一台机器可能十分钟内三种结果
  （TUN 通 / 直连超时 / 代理通）—— 插件按「实际能不能拿到数据」选路，
  而不是按 IP 段猜。

## 仓库里没有任何你的数据

这个仓库**只有代码**。插件跑起来产生的个人数据全在你的家目录（`$DSH_HOME/pixiv-scroll/`），
一个字都不在仓库里：

| 文件 | 是什么 |
|---|---|
| `credential.json` | 登录用的 refresh_token |
| `taste.json` | 本机学出来的口味画像 |
| `account-taste.json` | 从你登录的 pixiv 账号读来的那份喜好 |
| `quota.jsonl` / `ledger.jsonl` | 额度计数 / 存图台账（你存过什么、删过什么） |
| `bookmarks.json` | 你的收藏列表缓存 |
| `library/`、`cache/` | 存下来的图、候选缩略图 |

它们全在 `.gitignore` 里，而且有一条自检断言**从代码自己的路径函数取这份清单**逐个核对 ——
以后再加新的个人数据文件，忘了加进 `.gitignore` 会**直接报红**，
不会等你 `git add -A` 之后才发现。源码、测试、注释里也不放真实 userId / 账号名 / 本机路径。

**出厂默认也是中性的**：没有关键词、没有标签权重、没有保存路径、没有代理/外部源地址，
登录和口味画像都默认关。有另一条断言盯着这排默认值 —— 谁把自己的偏好写进 `DEFAULTS`，
一跑自检就报红。
